§3b · iOS TYPE SCALE — named steps, hard floor (v6.46)

The native app sizes text in points on a six-step scale. Every text node in the game sits on a step — no off-scale sizes. The constants live in CRT.Font (ios/Rendering/CRT.swift) and every label in the app renders through CRT.Font.of(), which clamps to the floor: text below the minimum cannot render anywhere, by construction.

stepptconstantuse
caption14CRT.Font.captionfine print, chip meta, footnotes, dim hints — THE HARD MINIMUM
label16CRT.Font.labelstat rows, list meta, HUD counters, secondary buttons
body18CRT.Font.bodySizedescriptions, help copy, prompt questions
heading20CRT.Font.headingpanel headers, item names, standard buttons (PixelButtonView default)
title22CRT.Font.titlescreen titles; Press Start 2P renders title-weight at smaller pt (≈12–16)
display28+CRT.Font.displaySizeheroes: wordmark, big numerals, overlay banners — sized to container, never below title
The floor is 14pt, picked on device (-typeRamp 1 renders the specimen): 13pt VT323 on felt fails the arm's-length read on an iPhone — the muted (0.62 alpha) variant doubly so — and 14pt is the first comfortable step. CRT.Font.of() enforces it: passing a smaller size renders 14.
When copy stops fitting, the fix is the layout, never the size: cut words, widen the container, or reflow. Passing a sub-floor size is a silent no-op by design, so a "sneaky shrink" is impossible.
Press Start 2P note: the display face runs ~1.7× wider/heavier per point than VT323. Display-face text at ≥12pt reads at label weight or better; the 14pt floor applies to its rendered presence, and Font.of clamps it the same way. Numeric-only badges (pile counts, histogram digits) are text and obey the floor — no exceptions.

§10 · Hard rules (perf + pixel)

  • Pixel grid: borders 2–4px; offsets/shadows in 2px steps; square corners ONLY (border-radius: 0 everywhere).
    Refined in practice (chunk 6 sweep): 1px is additionally legal at exactly two scales — hairline ROW/TABLE separators (this page's own list/table rules use them) and sub-24px micro-elements (mini-cards, count pills, node badges) where a 2px frame would swallow the face. Fractional borders (1.5px) are banned — they were swept to var(--px).
  • Shadows: box-shadow: 4px 4px 0 0 #000 (2px at 50% scale) — never blurred, never colored.
  • Glow: static text-shadow: 0 0 6px rgba(78,240,138,.55) on phosphor elements only. Never animated, never on other colors.
    Refined in practice: the SAME recipe may ride box-shadow: var(--glow) on small phosphor-bordered chips (Same-charge chip, revealed deck stack) — one glow, one strength, phosphor only.
  • Texture: baked dither tiles (data-URI GIF/PNG) — no gradients-as-texture, no runtime filters. (The CRT overlay's scanline/vignette images are the one sanctioned gradient use: they're the CRT, not texture.)
  • CRT overlay: ONE static fixed layer, pointer-inert, zero per-frame work. Flicker one-shot ≤240ms on big events only.
  • No new continuous animations. Existing animation *count* may only go down. All THERMAL bans hold: no full-viewport backdrop-filter, no box-shadow pulses, no blanket will-change, no filter loops.
  • Fonts: VT323 body + Press Start 2P display, self-hosted woff2 in app/assets/fonts/, loaded in BOTH paths (online link block + offline fonts.css); font-smoothing: none.
  • PERFCAP wrapped function names must survive untouched (tests/perfcap.test.mjs pins them).
  • Sounds that clash with the theme: FLAG for the later audio pass, do not change.
